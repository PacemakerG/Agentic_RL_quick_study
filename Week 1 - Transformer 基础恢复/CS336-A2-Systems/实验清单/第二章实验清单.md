## 实验顺序

### 1. 搭基础测速脚本

对应 `benchmarking_script (a)`，第 3–4 页。

- [x] 新增 `cs336_systems/benchmark.py`，复用 `BasicsTransformerLM`、`cross_entropy`、`AdamW`。
- [x] 支持模型规模、batch、序列长度、预热步数、测量步数和 CSV 路径。
- [x] 支持 `forward`（仅前向）、`backward`（前向＋loss＋反向）、`train`（前向＋loss＋反向＋AdamW）。
- [x] 默认预热 5 步、测量 10 步；计时前后同步 CUDA；保存样本、均值、标准差。
- [x] 通过 Ruff、语法、CLI 和参数检查；临时缩小模型并改为 CPU，验证三种模式的真实计算、预热排除、CSV 创建与追加。CPU 测试改动仅在内存中，未写入正式脚本。
- [ ] 在 CUDA GPU 上验证 small 的三种模式，并保存正式结果。

本步只搭建 FP32 端到端测速基础设施。模型初始化、数据生成、清空梯度和结果写入不计时。
仅前向模式关闭梯度记录；另外两种模式开启梯度记录。标准差使用 `statistics.pstdev`。
`backward` 输出的是前向＋loss＋反向的总耗时，不能当成单独的反向耗时。

在 A2 仓库根目录运行：

```bash
uv run python -m cs336_systems.benchmark --help

uv run python -m cs336_systems.benchmark --model-size small --mode forward
uv run python -m cs336_systems.benchmark --model-size small --mode backward
uv run python -m cs336_systems.benchmark --model-size small --mode train
```

自定义参数示例：

```bash
uv run python -m cs336_systems.benchmark \
  --model-size small \
  --mode train \
  --batch-size 4 \
  --context-length 512 \
  --warmup-steps 5 \
  --measure-steps 10 \
  --output results/benchmark.csv
```

结果默认追加到 `results/benchmark.csv`，每次运行写入一行，包含 GPU、PyTorch 版本、配置、均值、标准差和所有测量样本。
脚本采用从上到下的直接流程，没有额外的类或函数封装；后续实验需要新能力时再扩展。

## 执行注意

- 普通测速与 profiler 分开运行，避免 profiler 开销污染基准结果。
- 大模型先试跑显存，OOM 时记录准确配置；缩小模型用于调试不算完成原配置实验。
- 每批实验后立即保存结果并写简短结论。
- 当前机器为 Mac，实验 1 的正式 CUDA 测速仍需到 GPU 环境运行。
